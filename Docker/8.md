### 3\. Create the application

Create `app.py`:

```bash
nano app.py
```

Paste:

```python
from http.server import BaseHTTPRequestHandler, HTTPServer
import os
import json
import socket

class Handler(BaseHTTPRequestHandler):
    def do_GET(self):
        if self.path == "/health":
            status = 200
            body = {"status": "healthy"}
        elif self.path == "/":
            status = 200
            body = {
                "message": "Docker DevOps project is running!",
                "hostname": socket.gethostname(),
                "environment": os.getenv("APP_ENV", "development")
            }
        else:
            status = 404
            body = {"error": "Not found"}

        self.send_response(status)
        self.send_header("Content-Type", "application/json")
        self.end_headers()
        self.wfile.write(json.dumps(body).encode())

    def log_message(self, format, *args):
        print(format % args)

server = HTTPServer(("0.0.0.0", 8000), Handler)
print("Application listening on port 8000")
server.serve_forever()
```

Save: `Ctrl+O`, Enter, `Ctrl+X`.

This application provides two endpoints:

| Endpoint       | Purpose                         |
| -------------- | ------------------------------- |
| /              | Returns application information |
| /health        | Returns a basic health response |
| Any other path | Returns HTTP 404                |

### 4\. Write the Dockerfile

Create `Dockerfile`:

```bash
nano Dockerfile
```

Paste:

```dockerfile
FROM python:3.12-slim

ENV PYTHONDONTWRITEBYTECODE=1 \
    PYTHONUNBUFFERED=1

WORKDIR /app

COPY --chown=10001:10001 app.py .

USER 10001:10001

EXPOSE 8000

CMD ["python", "app.py"]
```

Why these settings?

* `python:3.12-slim` — a relatively small Python base image.

* `PYTHONUNBUFFERED=1` — helps application logs appear promptly.

* `WORKDIR /app` — sets the working directory.

* `COPY --chown` — assigns ownership to the non-root user.

* `USER 10001:10001` — runs the application as a non-root user.

* `EXPOSE 8000` — documents the application port.

### 5\. Create Docker Compose configuration

Create `compose.yaml`:

```bash
nano compose.yaml
```

Paste:

```yaml
services:
  web:
    build: .
    ports:
      - "8000:8000"
    environment:
      APP_ENV: development
    restart: unless-stopped
    healthcheck:
      test:
        - CMD
        - python
        - -c
        - "import urllib.request; urllib.request.urlopen('http://127.0.0.1:8000/health', timeout=2)"
      interval: 30s
      timeout: 3s
      retries: 3
      start_period: 5s
```

This configuration builds the image locally, publishes port 8000, configures the environment, and checks the health endpoint.

Important: The health check can report healthy only when the application responds successfully. `EXPOSE` alone would not publish the port.

### 6\. Create `.dockerignore`

```bash
nano .dockerignore
```

Paste:

```text
.git
.github
.env
*.pem
*.key
__pycache__
*.pyc
venv
```

This keeps unnecessary files and common secret files out of the build context. It is not a replacement for secret management.

### 7\. Build and run the project

First validate the Compose configuration:

```bash
docker compose config
```

Build and start:

```bash
docker compose up -d --build
```

Check the status:

```bash
docker compose ps
```

View logs:

```bash
docker compose logs -f web
```

Open a second terminal to test the endpoints:

```bash
curl http://localhost:8000/
curl http://localhost:8000/health
```

Expected responses will be JSON, similar to:

```json
{"status": "healthy"}
```

The root endpoint will return a message, hostname, and environment value.

Stop viewing logs with `Ctrl+C`; this stops log-following, not necessarily the container.

### 8\. Add a GitHub Actions workflow

Create `.github/workflows/docker.yml`:

```bash
nano .github/workflows/docker.yml
```

Paste:

```yaml
name: Docker CI

on:
  push:
    branches: ["main"]
  pull_request:
    branches: ["main"]

jobs:
  build:
    runs-on: ubuntu-latest

    steps:
      - name: Checkout repository
        uses: actions/checkout@v4

      - name: Validate Compose configuration
        run: docker compose config -q

      - name: Build Docker image
        run: docker build -t docker-devops-project:${{ github.sha }} .

      - name: Verify image exists
        run: docker image inspect docker-devops-project:${{ github.sha }}
```

This workflow validates the Compose file and builds the Docker image on GitHub-hosted runners. It does not push to a registry or deploy the application.

The `github.sha` tag ties the image reference to a particular commit, which helps identify what was built.

### 9\. Troubleshooting checklist

| Problem               | Command to investigate                                   |
| --------------------- | -------------------------------------------------------- |
| App doesn't start     | docker compose logs web                                  |
| Container exited      | docker compose ps -a                                     |
| Port 8000 is occupied | Change "8000:8000" to "8001:8000"                        |
| Health check fails    | docker inspect the container and check its health output |
| Build fails           | docker compose build --no-cache                          |
| GitHub Actions fails  | Open the failed workflow run and read the first error    |

For the health check, get the container name:

```bash
docker compose ps
```

Then inspect it:

```bash
docker inspect --format='{{json .State.Health}}' CONTAINER_NAME
```

Replace `CONTAINER_NAME` with the actual container name from your output.

When you're finished testing:

```bash

```

This removes the Compose-managed container and network. It does not delete your source files.
