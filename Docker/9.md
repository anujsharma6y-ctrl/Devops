
### Docker Swarm — Junior DevOps module

### 1\. What is Docker Swarm?

Docker Swarm lets you manage multiple Docker hosts as one cluster and deploy applications across them.

Swarm cluster

Multiple Docker hosts managed together

Manager node

Schedules and manages services

Worker node

Runs assigned tasks

### 2\. Important Swarm concepts

| Concept         | Meaning                                                                           |
| --------------- | --------------------------------------------------------------------------------- |
| Node            | A machine participating in the cluster                                            |
| Manager         | Maintains cluster state and schedules tasks                                       |
| Worker          | Runs assigned tasks                                                               |
| Service         | Defines the desired application and its configuration                             |
| Task            | A scheduled unit of work, typically a container                                   |
| Replica         | One instance of a service                                                         |
| Overlay network | Connects services across multiple Swarm hosts                                     |
| Routing mesh    | Allows published service ports to route traffic to service tasks across the swarm |

### 3\. Hands-on lab on one machine

You can practice the basics locally if Docker Engine supports Swarm mode. This lab does not require multiple servers, but it will not demonstrate real multi-host high availability.

Initialize Swarm:

```bash
docker swarm init
```

Check the node:

```bash
docker node ls
```

Deploy an Nginx service with two replicas:

```bash
docker service create \
  --name web \
  --replicas 2 \
  --publish published=8080,target=80 \
  nginx:alpine
```

Check the service and running tasks:

```bash
docker service ls
docker service ps web
```

Scale the service to four replicas:

```bash
docker service scale web=4
docker service ps web
```

Update the image:

```bash
docker service update \
  --image nginx:stable-alpine \
  web
```

Remove the service:

```bash
docker service rm web
```

Leave the Swarm when finished, if you don't need it anymore:

```bash
docker swarm leave --force
```

### 4\. Docker Swarm vs Kubernetes

| Feature                     | Docker Swarm                   | Kubernetes                                        |
| --------------------------- | ------------------------------ | ------------------------------------------------- |
| Setup                       | Generally simpler              | More components and setup                         |
| Orchestration               | Native to Docker Engine        | Dedicated orchestration platform                  |
| Scaling                     | Supported                      | Supported, with broader workload controls         |
| Self-healing                | Restores desired service tasks | Restores workloads through controllers            |
| Ecosystem and extensibility | More limited                   | Broader ecosystem                                 |
| DevOps job relevance        | Useful to understand           | More widely requested in many modern DevOps roles |

For your DevOps career: learn Swarm concepts and complete this lab, but prioritize Kubernetes and Helm for your next major orchestration module.
