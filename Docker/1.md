### 1\. What is Docker?

Docker is a platform for packaging and running applications in containers.

Imagine you build a Python application. It requires a particular Python version and some libraries. Another computer may have different versions and the application might fail.

Docker helps package the application and its dependencies into an image so it can run more consistently across supported environments.

Your application

Python code + libraries + configuration

Docker image

Packaged template

Docker container

Application process running in isolation

### The five important terms

| Term       | Simple meaning                     | Example                |
| ---------- | ---------------------------------- | ---------------------- |
| Image      | Template used to create containers | nginx:alpine           |
| Container  | Instance created from an image     | A running Nginx server |
| Dockerfile | Instructions for building an image | FROM python:3.12-slim  |
| Registry   | Stores and distributes images      | Docker Hub, Amazon ECR |
| Docker CLI | Tool used to issue Docker commands | docker run nginx       |

Image vs container: Image = template; container = instance. One image can create many containers.

### Docker vs virtual machines

| Docker container             | Virtual machine                     |
| ---------------------------- | ----------------------------------- |
| Shares the host's kernel     | Usually has its own guest OS kernel |
| Usually lightweight          | Usually needs more resources        |
| Typically starts quickly     | Typically takes longer to start     |
| Isolated application process | Separate virtualised machine        |

Containers still require proper security. They are not automatically as isolated as virtual machines in every situation.

### 2\. Docker architecture

When you run a command, multiple components work together.

Docker CLI

You type `docker run nginx`

Docker daemon — `dockerd`

Manages Docker resources and requests

containerd + OCI runtime

Help create and start container processes

Container

Your application runs

| Component                 | Responsibility                                   |
| ------------------------- | ------------------------------------------------ |
| Docker CLI                | Sends commands                                   |
| dockerd                   | Manages images, containers, networks and volumes |
| containerd                | Manages important container lifecycle operations |
| OCI runtime, such as runc | Sets up and starts container processes           |
| Docker Hub                | An image registry, not the Docker daemon         |

On Windows with Docker Desktop, the engine commonly runs in a Linux environment that integrates with WSL. Your Ubuntu terminal can connect to that engine.

### 3\. Install and verify Docker

If Docker is already installed, do not reinstall it. Open your WSL Ubuntu terminal or another terminal connected to your Docker Engine.

Run each command separately:

```bash
docker --version
```

Shows the CLI version.

```bash
docker version
```

Shows client and server details. If the server cannot be reached, the engine might not be running or the CLI might be connected to the wrong endpoint.

```bash
docker info
```

Shows server details, including the storage driver and container information.

```bash
docker ps
```

Lists running containers. An empty list is normal if you haven't started any.

### 4\. Run your first container

We'll use Nginx, a popular web server.

### Step 1 — Download the image

```bash
docker pull nginx:alpine
```

* `docker pull` downloads an image.

* `nginx` is the image name.

* `alpine` is the image tag.

### Step 2 — Start a container

```bash
docker run -d --name myweb -p 8080:80 nginx:alpine
```

Understand every part:

| Part         | Meaning                                 |
| ------------ | --------------------------------------- |
| docker run   | Create and start a container            |
| -d           | Run in the background                   |
| --name myweb | Give it the name myweb                  |
| -p 8080:80   | Map host port 8080 to container port 80 |
| nginx:alpine | Image to use                            |

### How port mapping works

Your browser

`http://localhost:8080`

Host port 8080

Container port 80 — Nginx

Open `http://localhost:8080` in your browser. You should see the Nginx welcome page.

If port 8080 is already in use, try `-p 8081:80` and visit `http://localhost:8081`.

### 5\. Container lifecycle — the most important commands

A container moves through different states during its lifetime.

Created

Container exists, but its main process hasn't started

Running

Main process is running

`docker stop`

`docker start`

Stopped

Container still exists, but its main process has stopped

Removed

Container object is deleted

Try these commands using the `myweb` container you created.

| Command              | What it does                                       |
| -------------------- | -------------------------------------------------- |
| docker ps            | Lists running containers                           |
| docker ps -a         | Lists all containers, including stopped ones       |
| docker stop myweb    | Stops the container                                |
| docker start myweb   | Starts an existing stopped container               |
| docker restart myweb | Restarts the container                             |
| docker rm myweb      | Removes a stopped container                        |
| docker rm -f myweb   | Force-removes a container, including a running one |

Remember: `docker stop` does not delete the container. `docker rm` removes it. Removing a container does not automatically remove its image or separately stored named volumes.

### 6\. Inspect images and containers

DevOps engineers regularly inspect containers when something isn't working.

```bash
docker images
```

Lists local images.

```bash
docker inspect myweb
```

Shows detailed container configuration, including networking, mounts and state.

```bash
docker logs myweb
```

Displays the container's recorded standard output and error logs.

```bash
docker logs --tail 50 myweb
```

Shows the last 50 log lines.

```bash
docker stats
```

Shows live resource usage for running containers, including CPU and memory.

```bash
docker image history nginx:alpine
```

Shows image layers and the commands associated with them.

### Which command should you use?

| Problem                          | First command to try |
| -------------------------------- | -------------------- |
| Is my container running?         | docker ps -a         |
| Why did it exit?                 | docker logs myweb    |
| What configuration does it have? | docker inspect myweb |
| Is it using too much memory?     | docker stats         |
| What images are installed?       | docker images        |

### 7\. Enter a running container

Sometimes you need to inspect files or run commands inside a container.

```bash
docker exec -it myweb sh
```

Meaning:

* `exec`: execute a command inside an existing container.

* `-i`: keep standard input open.

* `-t`: provide a terminal.

* `sh`: open a shell.

Inside the container, try:

```sh
nginx -v
```

```sh
ls /
```

Then type:

```sh
exit
```

You return to your own terminal. The container continues running because you exited the shell, not Nginx.

Important distinction:

* `docker exec` runs an additional command inside a running container.

* `docker run` creates a new container and starts it.

* `docker attach` attaches to the main process's existing input/output streams.

Not every image contains `bash`; lightweight images often provide only `sh`.

### 8\. Container vs image commands

This distinction prevents many beginner mistakes.

| Task                         | Command                  |
| ---------------------------- | ------------------------ |
| Download an image            | docker pull nginx:alpine |
| Create and start a container | docker run nginx:alpine  |
| List containers              | docker ps -a             |
| List images                  | docker images            |
| Stop a container             | docker stop myweb        |
| Remove a container           | docker rm myweb          |
| Remove an image              | docker rmi nginx:alpine  |

If Docker refuses to remove an image because a container still references it, remove the relevant container first.

### 9\. Common beginner mistakes

Mistake 1: The container exits immediately

Containers normally stop when their main process exits. Check `docker ps -a` and `docker logs CONTAINER_NAME` to investigate.

Mistake 2: The website doesn't open

Check that the container is running, the correct host port is published, and the application is listening on the expected container port.

Mistake 3: `docker exec` fails

The container must be running. Also, the image must contain the command or shell you are trying to execute.

Mistake 4: Docker cannot connect to its daemon

Check that Docker Desktop or your Linux Docker Engine is running and that your CLI is connected to the correct engine.

### 10\. Hands-on lab — complete the lifecycle yourself

Run the following steps in order. If you've already created `myweb`, reuse it rather than trying to create another container with the same name.

### Lab checklist

0/13

1. Verify Docker

docker version

2. Download Nginx

docker pull nginx:alpine

3. Run the web server

docker run -d --name myweb -p 8080:80 nginx:alpine

4. Check its state

docker ps

5. Open the website

Visit http://localhost:8080

6. Read the logs

docker logs myweb

7. Inspect configuration

docker inspect myweb

8. Open a shell

docker exec -it myweb sh

9. Exit the shell

Type exit inside the container

10. Stop the container

docker stop myweb

11. Verify stopped state

docker ps -a

12. Start it again

docker start myweb

13. Final cleanup

docker stop myweb && docker rm myweb

The final cleanup command removes the container, not the image. If you want to keep `myweb` for later practice, skip the final cleanup step for now.
