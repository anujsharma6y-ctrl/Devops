### 2\. What is a Docker registry?

A registry stores and distributes Docker images. A repository inside the registry stores related image versions.

### Important terms

| Term       | Meaning                                            |
| ---------- | -------------------------------------------------- |
| Image      | Packaged application and its filesystem layers     |
| Registry   | Service that stores and distributes images         |
| Repository | Collection of related images and tags              |
| Tag        | Human-readable image label, such as 1.0            |
| Digest     | Content-addressed identifier for an image manifest |
| push       | Upload an image to a registry                      |
| pull       | Download an image from a registry                  |

Example image reference:

```text
docker.io/myusername/myapp:1.0
```

This represents the Docker Hub registry, repository `myusername/myapp`, and tag `1.0`.

### 3\. Hands-on Lab A — Build, tag, and run an image

We'll use the Python app from an earlier module if you still have its project directory. Otherwise, create a fresh project.

### Step 1: Create a project

```bash
mkdir docker-registry-lab
cd docker-registry-lab
nano app.py
```

Paste:

```python
from http.server import BaseHTTPRequestHandler, HTTPServer

class Handler(BaseHTTPRequestHandler):
    def do_GET(self):
        self.send_response(200)
        self.send_header("Content-Type", "text/plain")
        self.end_headers()
        self.wfile.write(b"Deployed with Docker!")

HTTPServer(("0.0.0.0", 8000), Handler).serve_forever()
```

Save using Ctrl+O, Enter, Ctrl+X.

### Step 2: Create the Dockerfile

```bash
nano Dockerfile
```

Paste:

```dockerfile
FROM python:3.12-slim
WORKDIR /app
COPY app.py .
EXPOSE 8000
CMD ["python", "app.py"]
```

Save and exit.

### Step 3: Build the image

```bash
docker build -t myapp:1.0 .
```

Verify:

```bash
docker images
```

### Step 4: Add a registry tag

Replace `YOUR_DOCKERHUB_USERNAME` with your actual Docker Hub username:

```bash
docker tag myapp:1.0 YOUR_DOCKERHUB_USERNAME/myapp:1.0
```

The tag doesn't rebuild the image; it creates another reference to the same image content.

### 4\. Push the image to Docker Hub

Only do this step if you have a Docker Hub account and want to publish the image.

* Create a repository named `myapp` on Docker Hub.

* Log in from your terminal:

```bash
docker login
```

3\. Push your tagged image:

```bash
docker push YOUR_DOCKERHUB_USERNAME/myapp:1.0
```

Don't put your password or access token directly in a command or source file. Use Docker's supported login flow and follow the authentication prompts.

Security note: Anything pushed to a public repository can be downloaded by other people. Never publish secrets or sensitive data in an image.

### Step 5: Test pulling the image

You can test the registry copy by pulling it on another machine. Or, for a basic local test:

```bash
docker pull YOUR_DOCKERHUB_USERNAME/myapp:1.0
```

A pull may reuse locally cached image layers, so it doesn't necessarily prove that every layer was downloaded again.

### 5\. Troubleshooting common Docker failures

Use this order: check status → inspect logs → inspect configuration → fix the cause → retest.

| Problem                        | Useful command              | What to investigate                  |
| ------------------------------ | --------------------------- | ------------------------------------ |
| Container exits                | docker ps -a                | Exit status and startup command      |
| Application crashes            | docker logs CONTAINER       | Python errors, missing files, config |
| Port already occupied          | docker ps                   | Another service using the host port  |
| Image not found                | docker images               | Image name, tag, registry reference  |
| Permission denied              | docker inspect CONTAINER    | User, file ownership, mounted paths  |
| Container uses too much memory | docker stats                | Memory use and configured limits     |
| Build fails                    | docker build -t myapp:1.0 . | Dockerfile syntax and build output   |

### Useful diagnostic commands

```bash
docker ps -a
docker images
docker logs --tail 100 CONTAINER_NAME
docker inspect CONTAINER_NAME
docker stats
docker system df
```

Be careful with cleanup commands such as `docker system prune`: they can remove unused resources you intended to keep.

### 6\. CI/CD — Automate Docker builds

Instead of building and pushing an image manually every time, a CI/CD pipeline can do this when code is pushed to GitHub.

GitHub repository

Developer pushes a code change.

GitHub Actions

Runs tests and builds the image.

Image registry

Stores a versioned image.

Deployment

A deployment process pulls and runs the approved image.

### Example GitHub Actions workflow

Save this as `.github/workflows/docker.yml` in your GitHub repository:

```yaml
name: Build Docker Image

on:
  push:
    branches: ["main"]
  pull_request:
    branches: ["main"]

jobs:
  build:
    runs-on: ubuntu-latest

    steps:
      - name: Checkout code
        uses: actions/checkout@v4

      - name: Build image
        run: docker build -t myapp:${{ github.sha }} .
```

This workflow checks out the code and builds an image on pushes and pull requests targeting `main`. It does not push to a registry or deploy anything.

For a production pipeline, add tests and security scanning, then configure registry authentication using repository secrets or a supported identity federation mechanism. Only push or deploy from trusted events and approved branches.
